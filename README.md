# Gevix

Marketing site for Gevix, a design and engineering studio.

- `index.html` – home
- `work.html` – case studies (`/work`), generated in part from `content/work/*.json`
- `blog.html` – writing (`/blog`), generated in part from `content/posts/*.json`
- `blog/<slug>.html` – one page per article (`/blog/week-five`), generated by `build.py`
- `post.html` – legacy redirect from the old `/post#slug` links
- `admin/` – [Decap CMS](https://decapcms.org) at `/admin`, for editing posts and case studies without touching JSON by hand

## Run locally

```bash
npx serve .
```

## Editing content

Two ways to do it:

1. **Through the CMS** — go to `/admin`, log in with GitHub, edit a post or case study, publish. This commits the change straight to `main`, Vercel redeploys, and the site rebuilds automatically. Nothing to run locally.
2. **By hand** — edit a file in `content/posts/` or `content/work/`, then run `python3 build.py` to regenerate `blog/*.html`, the post/case-study listings in `blog.html`/`work.html`, and `sitemap.xml`. Commit everything, including the generated files (Vercel also regenerates them on deploy, so a stale local commit isn't load-bearing, but keeping them committed means `npx serve .` works without a build step).

Content model:
- `content/posts/<slug>.json` — one file per blog post. `body` is markdown (headings with `##`, lists with `-`, blockquotes with `> `, `**bold**`, `` `code` ``, `[text](url)` links — that's the full supported set).
- `content/work/<slug>.json` — one file per case study. `mockupHtml` holds the raw HTML for the bespoke device mockup (the fake dashboard/phone/browser screens) — copy an existing one as a starting point when adding a new case study.

`build.py` has no external dependencies (its own small markdown-to-HTML converter, no pip installs needed), so it runs as-is in Vercel's build step (`vercel.json`'s `buildCommand`).

## Setting up the CMS (one-time)

The CMS (`/admin`) uses Decap CMS's GitHub backend, which needs a small OAuth relay — that's what `api/auth.js` and `api/callback.js` are. To turn it on:

1. Create a GitHub OAuth App at [github.com/settings/developers](https://github.com/settings/developers) → New OAuth App:
   - Homepage URL: `https://gevix.in`
   - Authorization callback URL: `https://gevix.in/api/callback`
2. In the Vercel project's Environment Variables, add `OAUTH_CLIENT_ID` and `OAUTH_CLIENT_SECRET` from that OAuth App.
3. Deploy, then open `https://gevix.in/admin` and log in with a GitHub account that has write access to this repo.

## Deploy

Static site on Vercel, with `python3 build.py` as the build command (see `vercel.json`). `vercel.json` also turns on clean URLs so `/work` serves `work.html`, redirects `www` and the vercel.app host to `gevix.in`, and sets security headers.

## Before going live

- Client names, testimonials, case-study figures, author names and "since 2019" are placeholders — replace with real ones.
- Articles are ~200 words each; expand the ones that should rank.
- Verify the site in Google Search Console and Bing Webmaster Tools (submit `sitemap.xml`).
